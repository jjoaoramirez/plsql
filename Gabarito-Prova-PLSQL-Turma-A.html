Q01 Resposta correta: A — SELECT INTO + WHEN NO_DATA_FOUND

A loja LOJAVILELA precisa buscar o nome de um cliente para exibir na tela. O atendente digitou o código 99, que pode não existir. O sistema deve mostrar o nome se existir, e mostrar 'Cliente não encontrado' se não existir. Qual bloco faz exatamente isso?

Ver bloco correto
DECLARE
  v_nome CLIENTES.nome%TYPE;
BEGIN
  SELECT nome INTO v_nome
    FROM CLIENTES
   WHERE id_cliente = 99;
  DBMS_OUTPUT.PUT_LINE(v_nome);
EXCEPTION
  WHEN NO_DATA_FOUND THEN
    DBMS_OUTPUT.PUT_LINE('Cliente não encontrado');
END;

Por quê: B usa TOO_MANY_ROWS (errada para 0 linhas). C falta o INTO. D imprime a variável vazia no EXCEPTION.

Q03 Resposta correta: C — IF > 200, ELSIF > 100, ELSE

    FROM PRODUTOS
   WHERE id_produto = 10;

    DBMS_OUTPUT.PUT_LINE('Caro');

    DBMS_OUTPUT.PUT_LINE('Médio');
  ELSE
    DBMS_OUTPUT.PUT_LINE('Barato');
  END IF;
END;

Por quê: A falta o ELSE. B usa = em vez de >. D testa > 100 antes de > 200 e nunca chega em 'Caro'.

Q06 Resposta correta: D — FETCH → EXIT WHEN %NOTFOUND → imprime → CLOSE

A loja precisa imprimir o nome de TODOS os clientes ativos (ativo = 'S'), um por linha, até acabar. Qual bloco percorre todos e termina corretamente, sem imprimir linha em branco no final e sem deixar o cursor aberto?

Ver bloco correto
DECLARE
  CURSOR c IS
    SELECT nome FROM CLIENTES WHERE ativo = 'S';
  v_reg c%ROWTYPE;
BEGIN
  OPEN c;
  LOOP
    FETCH c INTO v_reg;
    EXIT WHEN c%NOTFOUND;
    DBMS_OUTPUT.PUT_LINE(v_reg.nome);
  END LOOP;
  CLOSE c;
END;

Por quê: A imprime antes do EXIT e gera linha em branco no fim. B não fecha o cursor. C faz FETCH em 2 variáveis para 1 coluna.

Q11 Resposta correta: C — Declara a exceção, levanta com RAISE e trata com WHEN e_estoque_baixo

Ver bloco correto

  e_estoque_baixo EXCEPTION;

  SELECT estoque INTO v_est

END;

Q12 Resposta correta: B — WHEN NO_DATA_FOUND e depois WHEN OTHERS com SQLERRM + RAISE

A loja quer tratar o caso 'cliente não encontrado' de um jeito, e qualquer OUTRO erro inesperado de outro jeito, sem esconder o erro. Qual bloco usa WHEN OTHERS corretamente, como última captura?

Q30 — Descritiva (até 0,6) — resposta modelo

Problema: Buscar com SELECT INTO o estoque e o estoque_min do produto id_produto = 20; com IF / ELSIF / ELSE, imprimir 'Repor urgente' se estoque < estoque_min, 'Atenção' se estoque = estoque_min, 'OK' nos demais; se o produto não existir, capturar a exceção e imprimir 'Produto não encontrado'. Usar %TYPE.

DECLARE
  v_estoque     PRODUTOS.estoque%TYPE;
  v_estoque_min PRODUTOS.estoque_min%TYPE;
BEGIN
  SELECT estoque, estoque_min
    INTO v_estoque, v_estoque_min
    FROM PRODUTOS
   WHERE id_produto = 20;

  IF v_estoque < v_estoque_min THEN
    DBMS_OUTPUT.PUT_LINE('Repor urgente');
  ELSIF v_estoque = v_estoque_min THEN
    DBMS_OUTPUT.PUT_LINE('Atenção');
  ELSE
    DBMS_OUTPUT.PUT_LINE('OK');
  END IF;
EXCEPTION
  WHEN NO_DATA_FOUND THEN
    DBMS_OUTPUT.PUT_LINE('Produto não encontrado');
END;
/

Critério: 0,2 SELECT INTO (2 colunas INTO 2 variáveis, FROM PRODUTOS, WHERE id_produto = 20) + 0,2 IF / ELSIF / ELSE (ordem e condições certas) + 0,2 EXCEPTION WHEN NO_DATA_FOUND. Em branco / Não Entregue = 0, sem zerar as objetivas.

Erros mais comuns que tiraram ponto: usar ELSEIF ou ELIF em vez de ELSIF; esquecer o bloco EXCEPTION; SELECT INTO com 1 variável para 2 colunas; usar = NULL em vez de IS NULL (isso era de outra questão, mas apareceu também); trocar as variáveis do INTO pelas declaradas.
